# scripts/

Contributor tooling for the local develop–build–deploy–test loop.

**Not needed for production installation.** If you just want to install
gitsync into an existing OIE server, download the release ZIP and drop it
into `$OIE_HOME/extensions/`. These scripts are only for developers who are
iterating on the plugin source and want to test against a local OIE instance
through OpenWebStart.

## Quick reference

```bash
cp scripts/dev-signing.properties.example scripts/dev-signing.properties
# edit scripts/dev-signing.properties to match your container names / URLs
./scripts/dev-setup.sh        # one-time
./scripts/dev-deploy.sh       # every rebuild
```

## Files

| File | Purpose |
|---|---|
| `dev-signing.properties.example` | Template for local config. Copy to `dev-signing.properties` and edit. |
| `dev-signing.properties` | Your local config. **Gitignored.** Contains keystore password and container names. |
| `dev-keystore.jks` | Self-signed keystore generated by `dev-setup.sh`. **Gitignored.** |
| `dev-setup.sh` | One-time environment setup. Idempotent — safe to re-run. |
| `dev-deploy.sh` | Per-rebuild build + sign + push + restart loop. |

## What `dev-setup.sh` does, and why

Each step is independently skippable via `SKIP_*=1` env vars, in case you
already have a working setup for some of them. The script is idempotent —
re-running it won't duplicate or corrupt anything.

1. **Generate a self-signed dev keystore** (`dev-keystore.jks`) if missing.
   OIE's admin console runs via OpenWebStart which requires signed JARs for
   JNLPs declaring `<all-permissions/>`, so we need *something* to sign with.
   Self-signed is fine for local testing; never use this keystore for
   anything that leaves your machine.

2. **Sign the ~223 base OIE JARs** inside each target container
   (`/opt/oie/client-lib/*.jar` and every `/opt/oie/extensions/*/*-{client,shared}.jar`).
   Only needed when your OIE was built from source with `-DdisableSigning=true`
   — official OIE releases ship their JARs signed and you can skip this step
   with `SKIP_BASE_SIGNING=1`. The JREs bundled inside OIE containers don't
   ship `jarsigner` (JDK-only tool), so the script tars JARs out to the host,
   signs them, and tars them back.

3. **Patch Reflections 0.9.10 → 0.9.12** in each container.
   OIE 4.5.2 bundles Reflections 0.9.10 which has a well-known
   `java.lang.IllegalStateException: zip file closed` bug on JDK 17+. It
   fires inside `com.mirth.connect.client.core.Client.<init>` when the
   admin console tries to log in, surfaces as the misleading
   *"error connecting to the server"* dialog, and breaks every login attempt.
   0.9.12 is API-compatible with 0.9.10, so swapping the JAR content (while
   keeping the filename so the JNLP reference still resolves) is a safe
   drop-in. The replacement is re-signed with our dev keystore.

   **This is an OIE upstream bug**, not a gitsync problem. Once OIE bumps
   Reflections in a new release, this step becomes a no-op and we can delete
   it from the script. `SKIP_REFLECTIONS=1` to skip.

4. **Import the dev signing certificate** into OpenWebStart's
   `~/.config/icedtea-web/security/trusted.certs`. Tells OpenWebStart that
   anything signed by our dev alias is trusted code.

5. **Import OIE's self-signed TLS server certs** into
   `~/.config/icedtea-web/security/trusted.jssecerts`. Without this, the
   initial HTTPS fetch of `webstart.jnlp` fails with
   `sun.security.provider.certpath.SunCertPathBuilderException: unable to
   find valid certification path to requested target` and OpenWebStart
   never gets as far as validating the JAR signatures.

6. **Pin OpenWebStart to a local Zulu 17 JVM** via
   `~/.cache/icedtea-web/jvm-cache/cache.json`. OIE's JNLP declares
   `version="1.9+"` which makes OpenWebStart happily pick its bundled
   Adoptium 21 — which trips additional Reflections issues beyond the 0.9.12
   patch. Zulu 17 avoids them. The script auto-detects SDKMAN-installed
   Zulu 17 first, then falls back to common system paths. Install one with
   `sdk install java 17.0.18.fx-zulu` if you don't have one.

## What `dev-deploy.sh` does

The daily-driver loop, run after every code edit:

1. `ant clean build` — produces `dist/gitsync-<version>.zip`.
2. Unzip the dist into a temp directory.
3. `jarsigner` every JAR in that temp tree (the three gitsync JARs plus the
   four bundled runtime libraries — JGit, JSch, SLF4J) with the dev keystore.
4. `docker exec rm -rf /opt/oie/extensions/gitsync` and
   `docker cp` the signed tree back in.
5. `docker restart` each target container (skip with `NO_RESTART=1`).
6. `pkill` any running `javaws` and purge `~/.cache/icedtea-web/cache` so
   the next admin console launch re-downloads everything fresh (skip with
   `NO_CACHE_PURGE=1`).
7. Print the exact `javaws` command to relaunch the admin console.

Multiple containers: `./scripts/dev-deploy.sh engine-oie-1 engine-oie-prod-1`
(overrides the `containers=` line in `dev-signing.properties`).

## Reverting everything

The scripts don't touch anything outside `~/.cache/icedtea-web`,
`~/.config/icedtea-web`, and the running containers — nothing system-wide.
To revert:

```bash
# Remove the keystore + config
rm -f scripts/dev-keystore.jks scripts/dev-keystore.cer scripts/dev-signing.properties

# Reset OpenWebStart to defaults
rm -rf ~/.cache/icedtea-web/cache ~/.cache/icedtea-web/jvm-cache/cache.json
# (the trust store entries can be removed via itw-settings GUI if you want)
```

The container-side changes (signed base JARs, patched reflections JAR) are
reverted on container recreation (not plain restart). `docker compose down &&
docker compose up -d` gets you a fresh unsigned OIE install.
